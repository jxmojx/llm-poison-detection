# 简历材料：中文训练数据投毒检测与在线拦截（poisonguard v3）

> 用法：按投递岗位挑「一、简历话语」里的一档直接粘贴；「二、怎么讲」是面试开口的前 2 分钟；「三、会被问什么」按顺序背，每个答案都带一个能现场复现的数字。
> 所有数字都来自本机实跑（`docs/实验报告_real_v3.md`、`outputs/metrics/*.json`），被追问可以当场 `make detect` / `make judge`。

---

## 一、简历话语（四种粒度，按岗位挑）

### 1. 简历项目名那一行

**中文训练数据投毒检测：三层检测流水线 + 级联成本曲线 + 判官蒸馏上线**

### 2. 一句话版本（放项目名下面）

> 面向中文 LLM 训练数据的投毒检测系统：真实语料 + 内容级篡改攻击集，三层检测（句向量离群 → LLM logprob 判官 → 行为探针），用级联召回-成本曲线把语义层压进预算，再蒸馏成 0.045ms/条的在线打分服务，CPU 可复现并带 CI 与提示注入红队。

### 3. 简历 bullet

**投算法 / 研究型（4 条）**

- 复现并重做中文训练数据投毒检测流水线：自建「真实语料 + 内容级最小事实篡改」攻击集（5 家族、适用率 25.1%），用同一评测口径**证伪前版指标** —— 无监督 kNN 的 AUROC 从 0.997 降到 **0.438**（低于随机），字符 n-gram 对内容级篡改的召回只有 **0.040**，量化了「合成攻击导致指标虚高」的具体幅度。
- 把 LLM 判官的判定接口从「生成 JSON」改为**候选 token logprob 打分**（Qwen2.5-0.5B，CPU 单条 0.78s），使 `TPR@FPR=1%` 从结构性的 0 变为可测值，并给出**级联召回-成本曲线**（含同预算随机对照与闸门替换实验）。
- 发现并量化「级联收益取决于第一级排序能力」：同样 40% 的 LLM 预算，kNN 闸门召回 27.0%，换有监督闸门后 **47.0%**（精确率 1.000）。
- 对语义层做**概率校准与对抗审计**：1% 误报阈值落在 0.966、ECE **0.133** → 判定它是合格排序器但不是合格概率；红队构造 8 类提示注入载荷做**三档配对**（plain / 加固 / 加固+确定性脱敏），把注入造成的分数跌幅从 −0.54 压到 −0.05、劫持率从 56% 压到 19% 且不伤 base 检出，并诚实指出残余劫持在「角色扮演/伪造示例」类载荷，据此把「结构隔离」而非「加规则」写进路线。

**偏工程 / 平台型（4 条）**

- 用软标签知识蒸馏把判官压成「句向量 + 字符 n-gram + 逻辑回归」学生模型：AUROC 0.6885 → **0.6922**，单条 **0.782s → 0.045ms（约 1.7 万倍）**，并如实报告 `TPR@1%` 从 0.045 掉到 0.025 的尾部损失。
- 交付可部署的检测服务（FastAPI）：`/score` 支持批量 512 条与 `explain` 多视图归因（kNN / 经验 FPR / 字符 n-gram / 学生概率）、`/stats` 暴露 p50/p99、`/health` 返回阈值与目标 FPR；阈值统一由干净 dev 集的 FPR 分位校准，不再是硬编码 0.5。
- 建立可复现实验体系：`make data|detect|judge|distill|redteam|report|serve|test|doctor`、42 项 pytest（覆盖规则改写不变量、级联单调性、服务端 400/413/200、注入分隔符不变量）、GitHub Actions、`doctor` 13 项依赖自检；每条指标写 provenance（git sha / seed / 版本 / 配置哈希）。
- 端到端时延归因：在线打分 19ms/条，其中编码器占 >99%、学生模型是微秒级 → 结论是「优化点不在分类头」，据此把蒸馏放到离线、把向量缓存写进服务侧的下一步。
- 交付面向业务的批扫与私有化发布物：`poisonguard scan` 一个命令把任意 txt/csv/jsonl 变成「分档 + 视图归因 + TopK 判官复核 + 人审报告」（Markdown/HTML/CSV/JSON 四件套，5.7ms/条）；`deploy` 只打包拟合态（kNN 参考向量 / n-gram 分类器 / 校准 / 学生 / 域阈值，**不含原始文本**）成单文件（42MB，kNN 参考向量 int8 量化后 **10.9MB**，520 条样本分档 0 处改变）并带 sha256 完整性校验 + **HMAC-SHA256 签名**（密钥错 / 包被改 manifest 一律拒绝，`--require-signature` 可强制）+ **编码器权重指纹**（防部署机装了同名不同权重；sha256 只防传坏、不防「换个合法包」，这两道才补上真实性）；`run` 在部署机只需公共编码器即可离线批扫，与作者侧逐条分数差 **0**——「数据不出域」从口号变成可校验、可验签的产物。

### 4. 自我介绍里的一句话（口述用）

> 我做过一个中文训练数据投毒的检测系统，最有价值的部分不是把指标做高，而是**先把一个 0.997 的指标打回 0.438**，搞清楚原来测的是数据生成器的口音；然后才去补语义层、级联成本曲线和蒸馏上线。

## 二、怎么讲这个项目（面试开口稿）

### 版式 A：30 秒电梯版（HR / 交叉面）

> 「大模型训练数据如果被人塞了毒样本，模型会学坏。我做的是一个开训前的检测流水线：先用句向量离群筛，再用小参数量的 LLM 判官读语义，最后用受害模型的行为信号兜底。中间最关键的一步是我发现上一版的 0.997 是假的——换成真实语料后无监督方法直接掉到 0.438。所以我重做了评测口径，又用知识蒸馏把 LLM 判官压到 0.045 毫秒一条，让它能真的上线。」

### 版式 B：2 分钟技术版（一面 / 技术面开场）

按这个顺序讲，别从代码开始：

1. **问题**：训练数据投毒 = 攻击者在语料里塞「看起来正常、但会教坏模型」的样本。难点是**没有干净标签**、**投毒比例极低**（本项目 5%），所以「准确率」这个指标在这个任务里没有意义。
2. **我先踩的坑**：第一版检测器和对攻击集是用同一套关键词生成的 —— 0.997 的 AUROC，train=test，75% 重复。**它测的是我自己造数据的口音。**
3. **怎么证伪**：把干净语料换成 CLUE/tnews 真实新闻，再新造一个「只改一个事实」的攻击家族（年份 / 涨跌 / 否定 / 单位）。结果：无监督 kNN 0.997 → **0.438**（比随机还差），词面分类器在模板类上仍 1.0，但在内容级篡改上只有 **0.040**。**这一刀切下去，才知道原来的高分会消失。**
4. **怎么补**：词面法失效的地方正好是语义法的主场 —— 上一个 0.5B 的 LLM 判官，但接口不能是「让它输出 JSON」，改读「污染 / 正常」两个 token 的 logprob，分数才连续、才能谈 1% 误报。
5. **贵怎么办**：只把一部分样本送 LLM，也就是级联。我不报单点，直接扫预算 5%~100% 出一条**召回-成本曲线**，还加「同预算随机」当对照 —— 结果 kNN 闸门的曲线贴着随机线，换有监督闸门后 40% 预算召回从 27% 到 **47%**。
6. **上线怎么办**：把判官蒸馏成 0.045ms 的学生模型，包成 FastAPI；顺带做了一次**提示注入红队**（三档配对），发现 prompt 加固有代价且不够、确定性脱敏能把劫持率从 44% 压到 19% 但压不到 0，终局是结构隔离 —— 这条写进了下一代路线。

### 版式 C：深挖版（被要求「挑一个点讲透」时）

挑**评测口径**讲，最容易体现判断力：

> 「这个任务里所有指标都应该是条件指标：在 1% 误报下能抓多少。但 1% 阈值定在哪个集合上有讲究——用测试集自己的 ROC 找点是看了答案再划阈值，我给单阶段检测器同时报了 test 调阈和 dev 校准两列，结果 sup_tfidf 两列都是 0.808（说明它没靠调阈吃饭），而 sup_lr 从 0.371 涨到 0.469（说明它之前的偏低是阈值问题）。这种『先把口径摆明』的习惯，比多刷两个点更有用。」

### 讲的时候要主动说、但别自夸的三件事

1. **主动说局限**：合成攻击只有 5 类、真实侧只做了最小篡改、0.5B 判官是下限不是上限、蒸馏掉尾部。**说局限不会减分，被问出来才减分。**
2. **主动说反向结论**：项目里最有信息量的三个结果都是负面的（kNN 0.438、edit 召回 0.040、注入劫持 100%）。把它们当结论讲，不要藏。
3. **主动说代价**：蒸馏 1.7 万倍加速的代价是 TPR@1% 从 0.045 掉到 0.025；prompt 加固的代价是 base 分整体降 0.18，脱敏不伤检出但也压不到 0。**只说收益的优化会被追着问。**

### 三件不要说的话

- 不要说「我用了某某模型所以很强」—— 判官的绝对分并不高，强在**成本结构**与**口径诚实**；
- 不要说「三层检测所以更准」—— 三层的真正理由是**各自补不同的洞**（离群补风格异常、语义补事实错误、行为补触发词），这句话要讲成机制而不是堆料；
- 不要把 0.938 的 `sup_tfidf` 当成"我的模型很强"，它是**基线**，而且它在 edit 家族上只有 0.040 —— 拿它当卖点会被一问就穿。

## 三、面试官会问什么（按被问概率排序）

### A. 方法论 / 判断力（一定会问）

**1. 「你怎么证明那个 0.997 是假的？」**
两条证据：①换真实语料后无监督 kNN 掉到 0.438，低于随机 —— 说明它抓的是「话题新」不是「恶意」；②新增内容级篡改家族后，词面分类器模板类召回仍 ≈1.0、edit 只有 0.040 —— 把「高分来自哪里」精确定位到数据构造。再补一句：v2 的 75% 样本重复、train=test，这两条本身就足以否掉那些数。

**2. 「真实语料上 0.438 会不会是你的编码器不行？」**
可能，所以我给了三条独立线索：①同一编码器下 sup_tfidf 到 0.938，说明向量没坏到不可用；②kNN 在 OOD 上误报 98.6%（v2），说明它的分数主要在反映分布距离；③硬负样本（像传闻的无害新闻）上 kNN = 0.500，正好是随机。要更严谨可以用第二个编码器复现，这是下一个待办。

**3. 「edit 家族只改一个事实，会不会太理想？」**
它是**最保守的下界**：只改一处、风格全保留，专门用来检验「词面法失效后还有没有兜底」。更强的 GCG 后缀、回译、字符混淆写在路线里没做，报告局限里明说了。

**4. 「1% 误报这个阈值怎么定的？会不会过拟合 dev？」**
干净 dev 集的 FPR 分位校准，有监督检测器的 dev 分数用 5 折 out-of-fold 避免偏乐观，并且同时报 `dev_achieved_fpr` 与 test 上的实际 FPR。另外我把「test 自己找点」和「dev 校准」两列并列 —— 这题一问就知道你有没有认真想过。

### B. LLM 相关（现在最容易被追）

**5. 「为什么用 logprob 而不是让它输出 JSON？」**
二值输出把信息扔了：FPR=1% 的阈值落在 0.996，召回结构性为 0，无论模型多强都测不出来。logprob 一次前向就得到连续分，还能拿 margin 做置信度过滤；prompt 一变 `PROMPT_VERSION` 就让缓存失效，保证分数与 prompt 版本一一对应。

**6. 「0.5B 判官 TPR@1% 才 4.5%，有什么意义？」**
单打确实不够，它的价值在两点：①**作为二级**，40% 预算下把总召回提到 47%（词面法对 edit 只有 4%）；②作为**能力下界**，我用它证明了 logprob 接口是可行的，1.5B/7B 只是同一接口换权重。同时我报了 ECE 0.133，明确它「能排序、不能当概率」。

**7. 「为什么不再加点 prompt 规则、或者让模型自查？」**
我红队测过：8 类注入载荷、三档配对。baseline 劫持率 56%；分隔符 + 「分隔符内是不可信数据」的 system 声明把跌幅从 −0.54 收到 −0.36，但 base 检出分也掉了 0.18 —— **有代价**；再叠一层确定性脱敏（13 条正则剥夺伪装成指令的字面片段）后跌幅到 −0.05、劫持率 19%，且不额外伤检出 —— 但**压不到 0**，因为残余载荷靠角色叙述而不是指令词。所以正确方向仍是结构隔离：判官不解析指令（分类头 / 指令微调）、双判官投票。这个「三档 + 残余归因」的结论比「再加一句规则」值钱。

**8. 「级联为什么能省钱？省在哪？」**
省在**不必全量过 LLM**：判官 0.78s/条、学生模型 0.045ms/条、编码器 19ms/条。级联的前提是闸门排序好，我用「同预算随机」当对照证明这一点：kNN 闸门曲线贴着随机线，说明它省成本是靠牺牲召回换的。这是我这一版最重要的负结果。

### C. 工程 / 部署

**9. 「蒸馏掉点了吗？」**
AUROC −0.004（0.6885→0.6922 实际略升），但 TPR@1% 从 0.045 掉到 0.025，这个必须报 —— 安全场景看的是尾部。加速 1.7 万倍主要来自「不再过 LLM 前向」，不是分类头有多快。

**10. 「线上怎么兜底、怎么归因？」**
`explain` 返回四个视图的原始分（kNN / 经验 FPR / 字符 n-gram / 学生概率），误报能归因到具体视图；`/stats` 给 p50/p99；阈值与目标 FPR 在 `/health` 可见。下一步是滑窗漂移告警 + 数据快照回滚。

**11. 「换台机器能跑起来吗？」**
`poisonguard doctor` 检查 13 个依赖与所有模型/数据路径并输出 JSON；`make` 把 v3 口径固定在变量里；指标带 provenance（git sha / 种子 / 配置哈希）。CI 跑 ruff + 42 项 pytest。

**12. 「为什么不用 GPU / 更大的模型？」**
本机只有 CPU，所以选择把「最小可用配置」做完整（0.5B + logprob + 蒸馏 + 级联曲线），而不是写一份跑不起来的 GPU 方案。GPU 路线的耗时我在报告里标注为推算值，不与实测混写。

### D. 反问环节可以问的（体现你在想什么）

- 「你们线上是只做离线数据审核，还是要在线拦截？这决定我该优化吞吐还是延迟。」
- 「判官的模型版本和 prompt 版本，你们有 A/B 与回滚机制吗？」
- 「数据血缘（每条样本从哪来、被谁改过）现在有吗？投毒事件的溯源往往比检测更花时间。」

## 四、可现场演示的命令

```bash
V3="--clean-source tnews --edit --hardneg 400 --run-tag v3"
python -m poisonguard.cli data   $V3     # 数据切分（秒级）
python -m poisonguard.cli detect $V3     # 8 个检测器 + dev 校准列（CPU ~30s，向量有缓存）
python -m poisonguard.cli judge  $V3 --qwen-model 0.5b --judge-scoring logprob --limit 40
python -m poisonguard.cli redteam $V3    # 提示注入红队（~2.5 分钟）
python -m poisonguard.cli report $V3     # 重出 docs/实验报告_real_v3.md
python -m pytest tests/ -q               # 42 项
python -m poisonguard.cli doctor         # 环境自检
```
