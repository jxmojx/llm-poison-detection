# poisonguard 架构总览

> 一句话：**训练数据投毒（poisoning）的「入库前」检测流水线**——数据进来先分层体检（词面/表示/模型/语义判官），再把判官蒸馏成毫秒级学生，最后打包成一个可签名、可离线跑的发布物。
>
> 代码量 11106 行（32 个模块）+ 2409 行测试（164 项）；26 个 CLI 子命令；4 个领域实测（tnews / iflytek / afqmc / real_v3）。

---

## 1. 分层架构（从下往上）

```
┌──────────────────────────────────────────────────────────────────────────┐
│  L5 交付层                                                                 │
│  cli.py (26 子命令)   service.py (FastAPI /score)   scan.py (批扫+人审报告)  │
│  deploy.py (.pkg 打包/签名/指纹/离线加载)   examples/*.py (演示)             │
├──────────────────────────────────────────────────────────────────────────┤
│  L4 语义层（LLM 判官，最贵也最有辨识度）                                     │
│  judge.py    Qwen 判官：logprob / 二值 / 启发式；prompt 注入加固 + 确定性脱敏  │
│  distill.py  判官 → 学生模型（TF-IDF+LogReg，0.15 ms/条，AUC 反超 teacher）   │
│  redteam.py  判官自己的攻击面：8 类注入载荷 × 三档（plain/hardened/sanitized）│
├──────────────────────────────────────────────────────────────────────────┤
│  L3 模型层（经典 ML 检测器，可解释、可校准）                                  │
│  detectors.py  8 个检测器 + Calibration(FPR 校准) + Fusion(加权融合)         │
│                 keyword / centroid / knn / mahalanobis / iforest              │
│                 sup_lr / sup_tfidf(CharNgram) / supervised                    │
├──────────────────────────────────────────────────────────────────────────┤
│  L2 表示层                                                                  │
│  encoders.py   CoROM 句向量 (768d) + 磁盘缓存 + 归一化 + ModelScope 下载       │
│  localmodels.py  本地模型目录解析/转义/缺失诊断                               │
├──────────────────────────────────────────────────────────────────────────┤
│  L1 数据层                                                                  │
│  data.py     读取/去重/切分/真实语料拉取/多字段兼容；产出 train/dev/test.jsonl │
│  attacks.py  5 个攻击家族：template / paraphrase / subtle / backdoor / edit   │
│  hardneg.py  硬负样本（像传闻但无害）挖掘与压力测试                            │
├──────────────────────────────────────────────────────────────────────────┤
│  L0 度量与契约层                                                             │
│  config.py   6 个 dataclass 配置 + YAML 加载 + 配置哈希                       │
│  evaluate.py AUROC / AUPRC / TPR@1%FPR(两口径) / ECE / bootstrap / McNemar   │
│              / 分家族召回 / 分群 FPR / 级联曲线 / 画图                        │
│  audit.py    词面审计（检测器抓的是"有害性"还是"没见过这种句式"）              │
│  victim.py   行为层：BERT 受害模型输出的置信度/熵/PPL（可选）                 │
└──────────────────────────────────────────────────────────────────────────┘
```

**为什么是这五层**：每一层解决上一层抓不到的东西。
- L1 决定"能不能测出结论"（真实语料 vs 混合语料，结论差一个数量级）；
- L2/L3 决定"便宜的检测器能到哪"（毫秒级、可解释、可校准，但抓不住内容级篡改）；
- L4 决定"语义能不能补上"（判官 0.95 s/条，抓得住改写，但贵且有自己的攻击面）；
- L5 决定"这套东西能不能交给别人用"（批扫 → 报告 → 单文件发布物）。

**依赖方向是严格单向的**（乱序即 bug）：

```
config ← 所有模块
attacks ← data ← cli
localmodels ← encoders/judge/victim
detectors + encoders ← service ← scan, deploy
judge ← distill, redteam
evaluate ← cli/report（只算，不 import 模型）
report ← 只读 json（不 import 模型/编码器）
```

唯一的"跨层捷径"是 `scan.py → service.build_scorer`（要装配）和 `deploy.py → service.build_scorer`（打包前的装配），这两个都在 L5 内部，可接受。

## 4. 指标口径体系（这是本项目最"值钱"的部分之一）

所有指标集中在 `evaluate.py`，报告只读 json，不允许别处重算。关键约定：

| 指标 | 口径 | 为什么这么定 |
|---|---|---|
| `tpr_at_fpr1` | 用 test 自己的 ROC 找阈值 | 乐观上界，跟论文可比 |
| `tpr_at_fpr1_devcal` | **只用 dev 干净样本定阈值**，拿到 test 上用 | 诚实口径，不许"看答案划阈值" |
| `auroc_ci` | bootstrap 1000 次 | 单点 AUROC 没有说服力 |
| `mcnemar` | 两个检测器配对显著性 | 0.938 vs 0.937 是不是噪声 |
| `recall_by_family` | 分 5 个家族分别算召回 | 总召回掩盖"edit 只有 4%"这种结构性失败 |
| `family_recall_at_0.5` | 固定 0.5 工作点 | 才能读出"哪个家族更难" |
| `fpr_ood` | OOD 样本单独报告 | OOD 天然离群，混进校准集会系统性低估 TPR |
| `ece` | 15 箱校准误差 | 判官"说得自信"不等于"说得准" |
| `cascade_curve` | 预算 k% 时的召回 | 级联是落地形态，必须报"花多少判官预算换多少召回" |

**三条被实测推翻的直觉**（都写进了文档）：
1. "阈值调优让数字虚高" → sup_tfidf 两列都是 0.808，不是主要来源；
2. "prompt 加固能挡注入" → Δ 只从 −0.95 收到 −0.36，劫持率仍 44%；
3. "模板攻击样本也能测出真实能力" → 模板能被 n-gram 抓 100%，换成 edit 后直接掉到 4%。

## 5. 当前数字基线（4 个领域）

| 领域 | 句长 | 最佳单阶段 | edit 召回 | 判官 AUROC | 学生 AUROC / 延迟 | 结论 |
|---|---|---|---|---|---|---|
| tnews（新闻标题） | ~25 字 | sup_tfidf 0.938 | **4.0%** | 0.6885 | 0.6922 / 0.045 ms | 内容级篡改是词面法死角 |
| iflytek（App 描述） | ~289 字 | sup_tfidf 0.898 | **1.4%** | 0.7208 | **0.7673** / 0.152 ms | 句越长，单点篡改越被淹没 |
| afqmc（问句对） | ~13 字 | sup_tfidf 0.990 | **67.4%** | — | — | 短文本域词面法就够 |
| real_v3（v3 主口径） | ~25 字 | sup_tfidf 0.938 | 4.0% | 0.6885 | 0.6922 / 0.045 ms | — |

**卖点不是"分数高"，而是把边界量化了**：什么时候词面法就够（短文本 67%）、什么时候必须上判官（长文本 1.4%）、判官贵多少（0.95 s vs 0.045 ms，2 万倍）、蒸馏能不能保真（AUROC 反超，TPR@1% 掉 45%→25%）、判官自己会不会被注入（三档 56%→44%→19%）。

## 6. 已知边界（主动写在文档里的"不能做"）

1. 攻击只有 5 个家族，~~没有自适应攻击~~（**已有**：`detect --evade` 量化了"攻击者知情"下的词面逃避，结论是压不动 edit，见 A4 ✅）；
2. 判官只有 0.5B（CPU 可跑），1.5B 没实测过上限；
3. 学生模型抓不住 edit（TopK 富集 0.4~0.7× 随机），排序层需要换思路；
4. 只有中文、3 个领域，跨语言/代码/对话未验证；
5. 没有真人标注一致性（判官 vs 人标的 kappa 未知）；
6. ~~在线服务无队列/限流/监控，是"能跑"不是"能扛"~~ ✅ **已完成**（环节 30-34）：`security.py` 鉴权（X-API-Key 多 key 常量时间比较 + admin 双权限）+ 每 key 令牌桶 429 限流 + sqlite 审计；`service.py` 热更新/版本切换（/admin/models｜reload｜switch｜rollback）+ 异步批处理（/batch）；`metrics.py` 零依赖 Prometheus /metrics；`docs/多实例部署.md` 多副本/外部队列/滚动发布方案。残余边界：限流/审计/批处理默认每实例独立，多实例需按文档做会话亲和或外部队列。

## 8. 代码结构上的技术债（诚实清单）

1. `cli.py` 1150 行：19 个子命令的 args + 派发 + 配置覆盖全在一起，改一个子命令要读 1000 行。
2. `report.py` 604 行：Markdown 拼接，模板逻辑与数字口径交织（已抽 `md_table`/`_fmt`）。
3. `deploy.py` 535 行：打包 + 签名 + 量化 + 加载 + CLI 入口，职责偏多，可拆 `pkg/`（format/sign/knn）。
4. `data/processed*` 有 5 个历史目录（`processed_real`、`processed_iflytek_iflytek` 是早期后缀 bug 的残留），可清理。
5. `train_qwen_lora.py` 未接 CLI，是"孤岛脚本"——要么接线成 `train` 子命令，要么明确标注"实验性"。
6. 无类型检查（mypy/pyright），dataclass 用得不错但函数签名没有 `->` 全覆盖。
7. `victim.py` 依赖 `baseline_model.pth`（1.4 GB 级），CI 无法覆盖，只能本地跑。

## 9. 一页纸的记忆版

```
输入：一条文本（或一个文件）
  └─ 编码器（CoROM 768d）
      └─ 8 个便宜检测器（kNN / 字符 n-gram / 马氏 / iforest …）→ 分数 0~1
          └─ 学生模型（蒸馏判官，0.045~0.152 ms）→ 更准的分数
              └─ 超阈值 → 判官（Qwen logprob，0.95 s/条）复核 → 人类可读理由
                  └─ 分档 BLOCK / WATCH / PASS + 人审报告
                      └─ 打包成 .pkg（拟合态 + 签名 + 指纹）→ 部署机离线跑

三个数字：edit 族词面召回 4%（死角）｜判官全量能拦 21/40｜学生 2 万倍加速但 TPR 掉一半
三个结论：短文本词面法就够｜长文本必须语义层｜判官自己会被注入（字面脱敏只能到 19%）
```
