## 路径二：干净机器全量复现（约 15–30 分钟）

按顺序执行（Windows 无 `make` 就逐条复制；有 make 可 `make doctor` 等）：

```powershell
# 1) 环境自检
python -m poisonguard.cli doctor
#    预期: 各项依赖 OK，qwen 权重 OK

# 2) 拉真实干净语料 CLUE/TNEWS（ModelScope，本机 HF 不通）
python -m poisonguard.cli download --corpus tnews
#    产物: data/raw/real_tnews.txt（19265 条唯一真实新闻标题）

# 3) 重建 v3 数据切分（真实干净侧 + edit 篡改 + hardneg）
python -m poisonguard.cli data --clean-source tnews --edit --hardneg 400 --run-tag v3
#    产物: data/processed_real_v3/{train,dev,test}.jsonl（test 5997 条）

# 4) 判官给抽样打分（Qwen2.5-0.5B logprob，CPU 约 5–8 分钟）
python -m poisonguard.cli judge --clean-source tnews --edit --hardneg 400 --run-tag v3 `
    --qwen-model 0.5b --judge-scoring logprob --limit 40 --dev-limit 20
#    产物: outputs/metrics/judge_samples_real_v3.jsonl（320 条）
#          + judge_samples_dev_real_v3.jsonl（160 条训练软标签）

# 5) 蒸馏学生模型（毫秒级排序器）
python -m poisonguard.cli distill --clean-source tnews --edit --hardneg 400 --run-tag v3
#    产物: outputs/metrics/student_judge_real_v3.pkl

# 6) 结构隔离判官（A1，冻结 Qwen 主干 + 二分类头，CPU 编码 4296+5997 条约 30-40 分钟）
python -m poisonguard.cli struct-train --clean-source tnews --edit --hardneg 400 --run-tag v3 --qwen-model 0.5b
#    产物: outputs/metrics/struct_real_v3.json + struct_head_real_v3.pkl

# 7) 保形预测（A2，读 4) 的分数缓存，秒级）：可证 FPR 上界 vs 实测
python -m poisonguard.cli conformal --clean-source tnews --edit --hardneg 400 --run-tag v3 --alpha 0.01
#    产物: outputs/metrics/conformal_real_v3.json（per-detector 阈值/上界/实测 FPR/TPR）

# 8) 判官注入红队（三档配对：plain / 加固 / 加固+确定性脱敏，0.5B CPU 约 6 分钟）
python -m poisonguard.cli redteam --clean-source tnews --edit --hardneg 400 --run-tag v3 --rt-each 2
#    产物: outputs/metrics/redteam_real_v3.json（injected.plain/hardened/sanitized + by_payload）

# 9) 复现场景四
python examples/repro_scene4.py

# 10)（可选）私有化发布物：打包拟合态 → 离线批扫（两条命令，数据不出域）
python -m poisonguard.cli deploy --clean-source tnews --real-file real_afqmc.txt --edit --hardneg 400 --sign-key demo-key
python -m poisonguard.cli run --bundle outputs/deploy/poisonguard-afqmc.pkg --input data/scan_demo_afqmc.txt --judge-topk 2 --sign-key demo-key
#   可选: --quantize i8（42→10.9 MB）；--require-signature（无签名不加载）

# 10)（可选）回归验证
python -m pytest tests/ -q        # 72 项全绿
```

> 注意：
> - PowerShell 换行续接符是 `` ` ``（反引号）；Git Bash / cmd 请写成一行或用 `^`。
> - `--qwen-model 0.5b` 必须显式，默认会去找 1.5B。
> - 步骤 4 的 `--limit 40 --dev-limit 20` 是每家族每 split 抽样数：8 族 × 40 = 320 条，正好是场景四拦截层的样本。

## 怎么读结果（诚实口径）

- **学生 TopK 对模板/改写类投毒富集 2–3×**（级联在这些家族上成立）；
- **对内容级 edit 不富集（≈0.4–0.7×随机）** —— 学生只用 160 条软标签训练，认措辞口音、认不出事实被最小篡改；
- **edit 的现实抓手是 LLM 判官 logprob**：全量 320 条中可拦 21/40 edit；要抓住 edit，需把复核预算给足，或换更强的排序器/判官。

这是修正了旧场景 D「用判官分排序 = 复核器自己排自己」自证问题后的诚实结论。
